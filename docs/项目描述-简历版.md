## 三段式（项目介绍 / 项目职责 / 项目成果）

> 多数学校简历模板要求这三块，直接按下面粘贴。数字已与当前代码库核对一致。

**运动会管理系统** ｜ 全栈开发（独立完成） ｜ 2026.05 – 2026.07

### 项目介绍

面向学校运动会的一站式管理平台，覆盖「线上报名 → 赛程编排 → 成绩录入 → 积分排行 → 破纪录审核」全流程，替代线下纸质报名与 Excel 人工汇总。系统采用三端协同架构：**微信小程序**面向学生选手（报名、查成绩、我的参赛项目、游客模式），**Vue 3 Web 管理端**面向老师与裁判（运动会/项目/赛程编排、成绩录入与一键晋级、积分维护、破纪录审核），**Spring Boot 后端**统一提供 RESTful 接口，所有响应走 `Result<T>` 统一封装。

技术栈：Spring Boot 4 / MyBatis / MySQL 8 / 华为云 OBS / JWT（HS384）· Vue 3 + TypeScript + Element Plus + Pinia + Vite · 原生微信小程序 · Docker + Nginx

规模：数据库 **19 张表**，后端 **97 个 Java 文件约 4356 行**，管理端 30 个文件，小程序 82 个文件。

### 项目职责

1. **架构与数据库设计**：独立完成三端架构落地与 19 张表的库表设计（逻辑外键关联、`utf8mb4`），制定「DDL 变更后必须同步维护 `sql/` 建表脚本」的约定，避免代码与线上表结构脱节。

2. **报名子系统**：实现组别级「每人限报 N 项」校验——沿 `participant → team → group_type` 三级链路取本人组别，用**带状态过滤的计数查询**统计已报名数（正确跳过已取消记录，解决取消后重报漏算）；通过 `event_schedule` 中间表把报名开放粒度精确到**「项目 × 赛次」**；支持一键晋级下一赛次并自动补报名。报名规则的维度（项目级名额、组别级限报）全部后台可配，规则调整无需改代码。

3. **成绩子系统重构**：将成绩的最小记录单位从 `event` 改为 `event_schedule`，解决同一项目预赛/决赛成绩**互相覆盖**的问题；按田赛/径赛区分单位（秒/米）做展示、排序与换算。

4. **账号体系改造**：把微信静默登录重构为账号密码体系（**BCrypt** 加密 + **JWT** 7 天有效期），编写一次性 Java 迁移脚本安全回填 30 条历史数据；实现 EasyExcel 批量导入参赛人员与重置密码；小程序新增登录页、改密码页、「我的参赛项目」页与游客模式。

5. **积分与破纪录**：实现代表队总分批量刷新、加减分调整流水（可追溯）、跨组别总积分榜 Top3 徽章展示，总分字段设为只读防手误；成绩达标自动标记为破纪录候选，管理端人工审核后以 `@Transactional` 事务性入册，保证成绩与记录状态一致。

6. **工程质量与部署**：统一 `Result<T>` 响应封装与 `GlobalExceptionHandler` 全局异常处理（业务错误统一 400）；`AuthInterceptor` 按路径白名单做 token 鉴权；纯逻辑抽离编写 **24 项单元测试**；完成 Docker + docker-compose + Nginx 容器化部署方案。

### 项目成果

1. **全流程线上化**：报名、编排、成绩、积分、破纪录 5 大环节形成在线闭环，学生在小程序端自助报名查成绩，老师不再需要纸质报名表和 Excel 汇总。

2. **规则可配置、少改代码**：项目级名额限制、组别级限报、项目×赛次的开放开关均由管理端配置，赛制调整只改数据不改代码。

3. **数据准确性提升**：成绩按赛次独立存储后，同级比赛的多轮成绩不再互相覆盖；24 项单元测试覆盖报名限报、成绩晋级、积分调整、破纪录入册等核心逻辑。

4. **两个月完成全栈交付**：2026.05–2026.07 独立完成需求分析、库表设计、三端开发与部署，累计 **119 次迭代提交**。

5. **可交付部署**：提供 Docker + docker-compose + Nginx 容器化方案，后端、管理端、小程序三端联调跑通。

## 面试可能被追问的点（备好答案）

- **限报校验怎么做、取消重报怎么不漏算？**（带状态过滤的计数查询，只统计未取消的报名）
- **为什么成绩要按赛次独立存？**（预赛/决赛同项目，存项目上会互相覆盖；加 `event_schedule_id` 作最小记录单位）
- **数据迁移怎么保证安全？**（先备份 → 一次性 Java 脚本回填 → 校验关联完整 → 迁移完成后清理临时代码）
- **项目是多人还是单人？**（单人全栈独立开发；文档化流程用于自管理）
- **数据库改动怎么维护一致性？**（强制约定：DDL 变更后必须同步更新 `sql/` 建表脚本）
- **Redis + Lua 用在哪、为什么用 Lua？**（报名防并发超报：名额/限报「检查+扣减」必须原子，拆成两条 Redis 命令会有竞态；用 Lua 脚本在 Redis 内一次执行保证原子性。积分榜缓存：热点读缓存、写回时经 Lua 原子更新。备选答法：也可用来做令牌桶限流）
- **Redis 与数据库的一致性怎么保证？**（缓存先失效或双写 + 定时刷新兜底；积分以数据库为准，Redis 只是加速层）
